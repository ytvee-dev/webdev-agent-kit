# 1.8.0 release preparation

## Acceptance

1. New promoted lessons need checkable declared support. Imported history remains
   intact; audit exposes gaps and recall excludes unsupported advice.
2. Applications, reviewed episodes and incorporated instructions remain separate
   from lesson freshness. Recall supports explicit multilingual aliases.
3. A session pause blocks event and attachment capture without enabling collection.
   Raw retention previews changes and preserves structured references.
4. Manual synchronization sends missing revisions and validates the combined
   relationship graph. No remote deletion or automatic sync is introduced.
5. Existing regression tests, package validation and all release archives pass.
   Record live-client gaps honestly before publishing.

## Release boundary

Prepare version 1.8.0 metadata, changelog, source PR and archives. Publication was explicitly approved after preparation. Merge the exact checked
commit with the release title; the version-specific workflow creates `v1.8.0`
and calls the existing release workflow to build and publish its assets.
Do not move an existing tag or copy private project records into release fixtures.

## Compatibility

All participating clients need v1.8 before writing optional v2 fields. Existing
record content is preserved. Raw retention is intentionally conservative when
source IDs or session provenance are missing. Native Windows capture and actual
model improvement require separate live verification; executable checks do not
establish either.

## Preparation evidence

- Existing learning suite: 29 tests, one Windows-only normalization check skipped
  on Linux. Scoped fixtures were maintained for the changed storage contracts.
- Full `validate_skill_pack.py`: passed source checks, generated target checks,
  offline routing and packaging checks, and 48 cross-client planning smoke cases.
- Ten versioned and alias archives built for v1.8.0; archive validation passed.
- Disposable legacy import preserved all records, excluded unsupported advice,
  and protected raw events when episode provenance was unknown. No private
  snapshot or identifying content is included in this repository.
- A disposable held-out evaluation allowed recall; changing its verdict to
  failed removed that lesson from recall. This verifies storage logic only.
- No authenticated live Codex/OpenCode executable was available. Native capture
  and model behavior remain unverified; fixture validation is not a live pass.
