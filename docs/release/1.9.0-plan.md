# 1.9.0 consolidated project learning release

## Source And Scope

The base is upstream v1.8.0. Layer the transferable STEM runtime rules onto that
base, then apply the user's explicit corrections from the chat. Preserve Kimi,
portable targets and protected project state. Do not replace the Kit with a host
checkout. STEM and ASI installations are read-only comparison sources.

`1.9.0-stem-inventory.json` inventories 243 transferable files plus the root policy,
with source/package hashes and comparison classifications. The original 42-file
learning inventory remains in `1.9.0-stem-source.json`. Generated graph metadata,
YAML quoting and authorized import/Windows fixes are packaging differences;
functional differences below are explicitly authorized, not a literal copy claim.
The added `test_learning_revision.py` is Kit regression coverage, not STEM source.
No host profiles, credentials, databases, transcripts or private paths are shipped.

## Functional Differences From STEM

- `learning_project.py`: new state has capture, telemetry and completion exchange
  off, no preset repository and no tracing configuration side effects. Existing
  settings survive. Legacy history requires explicit project-only migration.
- `learning.py`, `learning_memory.py`, `learning_cycle.py`: consistent project
  state resolution, both project flag forms, explicit state/environment precedence,
  actual state in status, local initialization and preserved explicit memory IDs.
- `learning.py` and `learning_memory.py`: triage excludes precisely curated event
  IDs; explicit reconsideration is separate. Session context uses bounded stable
  snapshot pages, with no silent loss of earlier or concurrently arriving events.
- `learning_exchange.py` and memory configuration: SQLite owns the verified remote;
  conflicting legacy addresses block sending. Configuring a remote never uploads.
  Completion exchange requires a separate stored choice; manual exchange remains
  explicit. Capture and single memory writes do not start exchange or analysis.
- `learning_tagging.py`: secret-free status and approved project enable/disable,
  credential shape, scoped authentication and override checks, credential reuse, tags and
  current-probe readback. Configuration alone is never ingestion evidence.
- `learning_telemetry.py` and `learning_workflow.py`: selected incident UTC windows,
  shared budgets, resumable cached receipts, filtered bounded archive context and
  database-only fallback. Lesson creation dates do not substitute for event dates.
- Learning discovery and instructions recognize explicit natural-language storage
  requests. The manual path writes an episode, evidence and a requirement without
  changing rules. Ordinary work does not silently become learning.
- Onboarding offers connection or decline, opens a private credential file when
  needed, waits for the user and configures supported hooks only after consent.
  Existing choices and other projects remain intact. Native trust is not bypassed.
- Root routing/output rules omit routine model/version/effort announcements.
  Trace/evaluation metadata is retained. Updater protections include local memory.

## Acceptance And Evidence

Use unit tests for storage, migration, curation, page cursors, state overrides,
remote conflicts, telemetry intervals, probe correlation and connection choices.
Use full source/target validation, lint, link checks and archive fixtures.
Record actual live-agent outcomes separately from synthetic runner validation.
Missing client capability is blocked evidence, never a passing behavior trial.
Real Langfuse account authentication/ingestion is not established by mock tests.
The final verification record is `1.9.0-verification.json`; local raw agent traces
remain private outside this repository.
