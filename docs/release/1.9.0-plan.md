# 1.9.0 release preparation

## Source comparison

The comparison baseline is v1.8.0, commit
`ada52938b678507f7ad9ce7c13309594ea5e1e13`. The installed project's managed
runtime inventory had 16 modified, 20 added and two removed paths, all under
`skills/agent-self-improvement/`. Local project overlays, transcripts, databases,
credentials and personal configuration are excluded from this source update.
Existing source graph metadata is retained and new references have source metadata.

The imported workflow separates capture, session curation, instruction changes,
behavioral evidence, application receipts and snapshot exchange. Source audit
removed a personal remote default and made telemetry and remote exchange explicit
configuration choices. Legacy background learning timers are removed.

## Issue acceptance

| Issue | Implemented contract | Acceptance evidence |
| --- | --- | --- |
| #85 | Project-local state, parsed CLI project resolution, visible database path, selected-project migration, Git exclusion | CLI/hook checks; isolated migration with unchanged legacy hashes; all 12 archive extractions preserve existing state |
| #84 | Latest complete curation covers exact event IDs; partial evidence remains pending; triage is not learning completion | Direct SQLite repeat/revision checks; context pagination and Unicode tests; capture/network remain separate opt-ins |
| #83 | Kimi Code project package, portable skills, explicit policy prelude, install guide | Package, parity and archive checks pass; live Kimi unavailable and explicitly unverified |

Migration rejects an absent legacy database or an unrelated project. It copies
selected project history and verifies database integrity without deleting the
source. Staging data and locks are ignored by Git before copying. Failed stages
remain local for inspection and cannot become the active store.

Telemetry restoration selects UTC event-day windows from the supporting evidence
graph. Windows share a request/page budget and stop after incomplete coverage.
Historical exports do not advance the general watermark. Missing observations
are not proof of success or exhausted quota. Partial evidence remains usable only
with its stated limitations.

## Verification evidence

- Existing learning suite passed all 78 tests. Focused checks additionally cover
  bounded context pagination, inline-data omission, Unicode and raw preservation.
- Markdown lint passed all 242 source files including this release document.
- Python lint and formatting passed. Formatting normalized Windows line endings;
  unrelated source content is unchanged.
- Generated planning parity, 56 cross-client planning smoke cases, version checks,
  Kimi structure and release archive fixtures passed.
- Synthetic behavior-runner checks passed. They do not run an AI model or prove
  improved agent behavior. No live Kimi client result is claimed.
- PR #86 CI passed all five checks on `e39a401`, including Windows and Linux native
  helpers. Windows short-path test fixtures now use canonical paths, matching
  generated proposal identity; the production identity check was not weakened.
- Exact-window telemetry caching checks cover reuse, missing archive files and
  expiry. Cached coverage is timestamped and never claims up-to-date remote data.
- All 78 learning tests passed again after cache changes. Twelve release archives
  were built and validated; extracting each over disposable existing memory and
  project configuration preserved their exact hashes.

## Final acceptance and limitations

- A disposable two-project migration verified selected events, attachment bytes,
  decision history and proposal bytes. Referenced external reports remained
  accessible; every original legacy file retained its hash. Legacy references
  can still point into the preserved old store. Do not delete that store or move
  external reports on the assumption that migration creates a standalone backup.
- Direct triage checks verified exact input IDs, repeat-run exclusion and reopening
  after a latest partial revision, while retaining both episode revisions.
- Codex CLI 0.164.0 was authenticated. The existing
  `learning-readaptation-consent` scenario ran against archived v1.8.0 and v1.9.0
  in separate disposable fixtures with the same client-default configuration.
  Both completed without file changes, but local instruction reads were rejected
  by the child client's policy. Consequently both remain behaviorally unverified;
  their final explanations are not proof of compliance with loaded Kit rules.
  No general model-improvement or live Kimi claim is made.
- Twelve checked archives, SHA256SUMS and notes are prepared in the draft v1.9.0
  release. Preparation does not merge the PR or publish the release. Recheck CI
  and the selected commit before those separate actions.

This release prepares source and distribution artifacts. It does not train model
weights, activate collection on installation, grant permission for unattended
learning, or publish any project's private memory.
