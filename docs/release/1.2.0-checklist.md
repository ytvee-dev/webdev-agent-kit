# 1.2.0 Claude Adaptation Release Checks

This document records the plan and checks for the version in its title. For
current setup, use the [installation guides](../install/README.md); for changes
by version, see the [changelog](../../CHANGELOG.md).

## Acceptance

- All 21 portable skills remain present in all six generated targets.
- Claude targets add nine native roles with minimal native metadata, inherited
  models, explicit tool allowlists and bounded task/report instructions.
- Claude skills resolve shared policy from the installed plugin; host context,
  native settings and custom agents remain outside the plugin and preserved.
- Onboarding, context refresh, review helpers and updates use Claude-specific
  discovery and freshness evidence without applying the Codex TOML bootstrap.
- Claude aliases remain byte-identical and existing Codex/Cursor contracts pass.

## Executable Evidence

The full `python scripts/validate_skill_pack.py` run includes 45 Codex helper,
16 review-package and seven Claude-role tests, with two Windows-only skips on
Linux. It also covers 48 planning contract cases and extracted archive fixtures.
Run existing Ruff, YAML/Markdown lint and local-link checks before publication.

Claude Code 2.1.296 was installed outside the checkout. Using an isolated
`CLAUDE_CONFIG_DIR`, the real CLI validated the plugin and marketplace manifests
in strict mode, registered the extracted archive as a local marketplace,
installed it and updated from 1.1.0 to 1.2.0. `claude plugin list --json` confirmed
enabled 1.2.0; `claude plugin details` listed 21 skills and nine agents.
The CLI manifest check alone does not validate native Markdown components;
the kit's role tests and real inventory provide separate evidence.

All ten stable/versioned archives pass extraction and checksum validation.
Repeated builds must produce identical bytes. No archive contains host settings
or local project facts; sentinel checks preserve existing host instructions,
`.claude/settings.json` and custom `.claude/agents`.

## Behavioral Limits

Three Claude-only scenarios cover plugin-root adaptation, role selection and
review handoffs in `evals/live/scenarios.json`. The runner validates preparation
and synthetic execution separately. Authenticated model behavior is unverified
without provider credentials and retained tool traces. Do not relabel CLI
discovery, model inheritance or written profiles as successful role invocation.
Windows regressions require the existing Windows CI matrix.

Official implementation guidance was inspected from
`anthropics/claude-code` at revision
`bf2323b3021c9d3db7a31e1e7d61068c3f704497`, including native agent definitions,
inheritance, tool allowlists, plugin layout and the documented
`${CLAUDE_SKILL_DIR}` substitution. The installed CLI supplies current command
contracts. Role taxonomy and dispatch recommendations remain Kit policy.

## Publication

Validate `v1.2.0` against all source metadata and changelog notes. Confirm the
release workflow for the exact tag and all five clients' stable/versioned assets
plus `SHA256SUMS`. Local builds, a pushed tag and a published release are separate
states; report only the states actually observed.
