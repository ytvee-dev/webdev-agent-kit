# 1.0.0 GPT Routing Validation

## Release Contract

Version 1.0.0 introduces optional instruction-driven GPT role setup, not an
always-on model gateway. No installed host settings are migrated automatically.
Normal onboarding and non-Codex clients preserve existing behavior.

## Reproducible Automated Checks

Run `python scripts/validate_model_routing.py` for positive/negative installer
regressions and policy/packaging contracts. Run
`python scripts/validate_skill_pack.py` for source graph, schemas, budgets,
workflow policies, scenario preparation, all client targets and archive checks.
Quality CI additionally checks Python formatting/lint, Markdown and YAML.

Installer tests use synthetic GPT catalog entries and disposable host roots.
They check deterministic TOML, standalone/registered layouts, no-op dry runs,
repeat installation, permission/availability gates, collisions, user drift,
configuration preservation, interrupted writes and rollback conflict handling.
These tests do not contact OpenAI, authenticate to Codex or grade a model.

## Authenticated Client Acceptance

Before claiming activation for a host, record its actual Codex version and
surface, authentication mode, confirmed model catalog, installed role hashes,
effective permissions and native delegation availability. Smoke-run each role
with a tiny read-only assignment and inspect actual model/effort metadata.
Verify reviewer fresh-context behavior separately. After a role/config change,
repeat affected canaries. Unsupported surfaces retain single-agent fallback.

Live role dispatch, instruction adherence and cost savings are not established
by static CI, fixture preparation, TOML parsing or supplied model labels.
They require observable runs in an authenticated client. Never report these
checks as passed when the environment cannot execute them.

## Economic Acceptance

Compare identical acceptance criteria in baseline single-agent and routed runs.
Include coordinator and all children, input/cache/output usage, retries,
verification, review, integration, latency and defects. Distinguish API currency
from subscription credits. Publish conclusions only with traceable results;
1.0.0 promises no fixed savings percentage or error-free model behavior.
