# 1.4.0 Self Learning Preview — Release Acceptance

This document records the plan and checks for the version in its title. For
current setup, use the [installation guides](../install/README.md); for changes
by version, see the [changelog](../../CHANGELOG.md).

## Scope

Ship opt-in local experience collection, offline triage, and a model-assisted **review-only** skill improvement cycle as the 22nd skill. Keep canonical Codex, Claude Code, Cursor contracts unchanged. No new OpenCode distribution target, unrestricted transcript scraping, or claims of complete universal attachment-byte capture.

## Safety And Consent

- OFF by default; explicit project opt-in through `learning.py on`.
- Private state outside public repositories; optional explicit attachment imports, SHA-256 blob naming, deduplication and per-project purge.
- Captured material is untrusted data. Collector never executes instructions from messages.
- Hook configuration is shipped as a sample, never installed, enabled or trusted automatically.
- Deterministic triage produces a report. Explicit model CLI execution may generate an isolated diff. Structural checks and user approval are required before applying; no automatic merges, pushes or PRs.
- Do not publish private transcripts, screenshots or samples from user projects.

## Required Checks

1. Schema, graph, inventory and trigger validation.
2. Synthetic CLI tests: disabled capture; enabled capture; dedup; correction evidence; opt-out; attachment authorization; purge.
3. Six distribution targets and archive checks; ensure only scripts/examples ship and no private records.
4. Ruff lint/format, YAML/Markdown lint, Windows and Linux helper tests.
5. Manual Codex hook trust and end-to-end test with real sanitized session.
6. Claude Code hook compatibility smoke test or explicitly leave as preview/unverified.
7. Optional OpenCode plugin smoke test against its current event and session API.
8. Reviewer verifies no replay of untrusted text as policy and no unauthorized settings or file writes.

## Release Gate

Do not merge the PR or publish v1.4.0 based only on static CI. Record real client evidence, check any privacy or hook behavior discrepancies, and require independent review. If live tests remain blocked, keep PR in draft. Model-backed proposals, isolated static validation and optional nightly analysis are implemented. A basic held-out A/B lexical regression gate is implemented, but authenticated live agent-task validation and complete cross-client attachment capture still require field evidence.
